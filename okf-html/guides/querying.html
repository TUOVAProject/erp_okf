Querying the Monitor API

Endpoint shape

Every documented endpoint follows one pattern:

GET  https://<host>/<language>/<company>/api/v1/<Module>/<Entity>
POST https://<host>/<language>/<company>/api/v1/<Module>/<Entity>/<Command>

The documentation renders the host as localhost:8001 with language sv and company 001.1 — these are placeholders for your own Monitor server, not a public endpoint. The /api/v1/<Module>/<Entity> tail is the stable part, and it is the endpoint value recorded on every entity page in this bundle.

What is in this bundle

  • 351 queryable entities — GET, returning a collection.
  • 4 commands — POST, listed in Modules. Their properties table is the request body, not a response shape.
  • 25 payload types — no endpoint of their own; they appear nested inside other responses or command bodies.

What is deliberately not in this bundle

The API's 913 command pages (POST operations that create, update or remove data) are excluded by the crawler. They live under Monitor.API.<Module>.Commands.* upstream and the crawler skips them by design, because the purpose of this bundle is to describe the data model comprehensively rather than the write API.

The 4 commands that are here are the ones the upstream documentation files outside that namespace; they are included for completeness, not because command coverage is a goal.

If you need a write operation, go to https://api.monitor.se/api/ and look under the module's Commands namespace.

Query options

Query options, filter functions and authentication are documented in Monitor's Developer Guide (https://api.monitor.se/articles/v1/index.html), which this bundle does not include.

Hints on the entity pages

  • Properties marked expandable (599 of them) are navigation properties that can be expanded.
  • One property summary (FormReportConfigurations Type) notes that $filter and $orderby cannot be used with it.
